# 007: Same-case inputs, response review and specialist responsibility

Date: 22 September 2026. Scope: PH-07, requested as the next phase after PH-06. Live Azure testing remains authorized; the browser target is desktop.

The five families share the existing model-driven worker and simulator services. New enabled tools inspect specialist tasks, create/reuse an authorized name-change task, perform its update and request an assessed handoff. The runtime does not contain a scripted scenario sequence. The live evaluation harness supplies synthetic presenter inputs and review decisions explicitly; it is not loaded into model context.

Typed case inputs update the selected synthetic case and preserve its original receipt timestamp, prior runs, sent responses, attachment copies, indexed PDFs and notes. Replacement evidence keeps its reference ID and increments its version; previous files are retained. Legal-name input supplies only the missing legal document: it cannot pre-complete the servicing update. Tax and bankruptcy inputs update the original scoped task and record that the result came from a presenter-supplied synthetic source. EFT input records the selected purpose without granting consent or funds authority. Missing authority, representative-only authorization, assignment conflict/resolution, separate concerns and unrelated contacts are explicit variants. Representative input cannot reverse cease-and-desist restrictions.

Presenter mutations reserve the SQLite write transaction, require a current case revision and persist a stable request receipt plus an actor-attributed event. Conflicting request reuse, cross-case references, active workers, unresolved uncertain actions and closed cases reject mutations. Material input increments the response basis and invalidates old drafts/reviews. Related loan snapshots are refreshed; unrelated loans are unchanged.

Review binds the latest unsent response ID/version, content revision, evidence/input hash and structured candidate. Returning a response requires a note. The reviewer editor changes supported structured claims, concern dispositions and attachments; it cannot insert unchecked prose, change a verified recipient or remove mandatory disclosures. The existing preparation/validation service creates a new version in the same transaction. Invalid edits leave the previous draft and case revision intact. An edit or new evidence requires a fresh approval. Required review is stored on the draft, so later automatic-mode or manual simulator calls cannot bypass it.

Resume creates a new linked run on the same case, re-observes current evidence and inherits the paused run's review mode. The agent sees current/sent/approved/returned draft state, reviewer notes, prior artifacts and remaining concerns. Approved responses reuse their existing version; sent interim responses are retained. Normal browser reads and refreshes never start or resend an action. Automatic recovery of an interrupted worker remains PH-08.

A specialist handoff is a persisted record of route, owner, concerns, evidence versions, restrictions and input hash. Repeating the request on the same inputs reuses it. Only acknowledgment of the current scoped handoff records a transfer. Transfer does not close the case or fabricate a specialist answer. A no-work restriction permits administrative responsibility tracking while response and servicing updates remain blocked.

The source policy deliberately has no approved operational taxonomy mapping for DEMO-01, DEMO-04 or DEMO-05. A successful name update can be confirmed, but classification review still prevents closure. Bankruptcy retains its classification exception and communication restrictions even after the supplied determination. EFT remains pending for the specified authorization/instructions. No mapping was invented to make an evaluation pass.

Live testing exposed an incorrect bankruptcy citation using a task ID. The validator rejected it. Tool guidance now distinguishes document/servicing citations from `task_completed`, which uses a task ID. The internal specialist determination is evidence for a claim, not an approved outgoing attachment. This improves model instructions without weakening response validation. Provider interruptions remain visible failed runs; their reports and partial artifacts are retained.

PH-05 is still partial: its persisted viewers and this reviewer editor are available, while a standalone manual prepare/execute workflow remains open. Broader role eligibility, C&D reversal, arbitrary prose authoring, real communications, funds movement and production authentication remain outside this release.
