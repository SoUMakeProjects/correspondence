# PH-10 — Built-in mailbox and connected workspaces

Status: **complete** (CP-10.1 through CP-10.6), verified on 22 September 2026. Application `0.9.0`, schema `0006`. Extension authorized by the user: use the built-in mailbox instead of Outlook and trigger one of five demos by sending its prepared email.

## Implemented behavior

- Five initial mail templates create independent cases. Prepared borrower replies remain on the original conversation and case. Message IDs make network retries idempotent.
- Durable server-side intake receives pending messages before scheduling new work. Mail, relevant input, response review and handoff acknowledgment trigger automatic runs. Event/run association commits with run creation.
- New evidence invalidates an older draft/approval before continuation. Concurrent pending mail is checked again while the next run is created. Multiple ready events for one case can share a run.
- An explicit stop remains stopped when new mail arrives. The operator's Resume queues continuation and processes pending mail first. Failed/uncertain actions retain the existing recovery controls.
- CCT, ILS, OnBase, secure mail, the mailbox and Review queue show the same persisted case/system records. OnBase opens the actual source and combined response PDFs. No browser-driven RPA is involved.
- Follow agent navigates using actual run/tool activity. Manual navigation disables following; server processing continues. Browser reload restores the linked case and conversation.
- Legacy cases remain available, with manual diagnostics at `/?workspace=classic`. Only mailbox-managed cases automatically react to workflow events.

Primary files: `backend/app/automation.py`, `mail_api.py`, `mail_contracts.py`, `mail_templates.py`, migration `0006_mailbox_automation.py`, `frontend/src/OperationsApp.tsx`, `Mailbox.tsx`, `SystemViews.tsx`, and their tests. Existing agent/workflow services supply action validation, receipts, versioned approvals and recovery.
