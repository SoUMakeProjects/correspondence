## Implemented behavior

The worker reclaims interrupted work under a new lease, reconciles verifiable effects and reconstructs a result committed before its checkpoint. Graceful shutdown requeues the same run. Recovery retains original start, history and usage; the elapsed limit includes outage/lease waits. A long outage can therefore pause at the time limit. Explicit resume creates a linked run with a new budget. A changed model configuration requires explicit continuation; presenter stop is never automatically undone.

The desktop exposes four single-use faults, verification and synthetic status-restoration controls, per-run summaries and a downloadable sanitized JSON reference manifest. Unknown effects keep further writes blocked. Restoring status access does not approve the original effect; its saved records/files still need to verify. Existing review/version/closure rules remain enforced. Recovery controls wait for current revision data after a mutation.

Metrics identify their scopes: action counts belong to the selected run, intervention counts include case history through that run, and pending concerns/current status reflect the case now. Reported usage is labeled incomplete when an interrupted request's totals were not saved. The export combines selected-run metrics with current case references at export time; it is not a historical snapshot or PDF bundle. See [decision 008](../decisions/008-recovery-and-evidence.md) and the [recovery walkthrough](../../README.md#recover-a-run-and-inspect-its-evidence).
